### T06b — `bin/omafan-keybindings` fix round (same files, defect list)
- **Goal:** fix the defects the orchestrator found in your T06 delivery. Same two
  files, same ownership; do not touch anything else.
- **Files (own):** `bin/omafan-keybindings`, `tests/keybindings.test.sh`.
- **Accepted as-is:** the managed-block surgery, idempotence, backup, marker
  detection (`grep -qxF -e`), conflict checks (live `hyprctl binds -j` +
  Lua-source scan incl. `code:` chords), `remove` restoration, `print`/`status`
  shape, exit codes. Do not regress any of it — your suite must stay green.
- **D1 (functional defect, must fix):** the emitted block calls a bare
  `omafan-ctl`, which is **not on `PATH`** — the plugin's `bin/` directory is not
  in `PATH`, and Hyprland runs a `bind ... exec` command through a plain
  non-login shell. Every preset/cycle chord would therefore fail with
  "command not found" while looking correctly installed. Resolve the helper at
  install time:
  `plugin_dir="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"` and
  `ctl="${OMAFAN_CTL:-$plugin_dir/bin/omafan-ctl}"`, then emit the absolute path
  in the block (the panel toggle chord keeps `omarchy-shell omafan toggle`, which
  *is* on `PATH`). Add `OMAFAN_CTL` to the documented overrides in the header.
- **D2 (guard, must add):** refuse to install (exit 1, write nothing, name the
  problem and the fix) when `$ctl` is not an executable file, or when its path
  contains a space, tab, `"`, `'` or `\` — the path is embedded inside a Lua
  string that Hyprland hands to a shell, and a quoting bug there fails silently at
  key-press time. Refusing loudly is the right trade.
- **D3 (visibility):** `print` and `status` must show the resolved `ctl` path, and
  `status` must report `stale-path` when the block on disk references a different
  helper path than the one that resolves now (e.g. the plugin moved), with the
  fix (`re-run install`).
- **D4 (tests, must add):** `tests/keybindings.test.sh` gains:
  every `o.bind(` command in the emitted block that calls the helper references an
  **existing executable inside the tempdir*; no bare `omafan-ctl ` token remains in
  the block; install refuses (exit 1, target untouched) when `OMAFAN_CTL` points at
  a missing file; install refuses when `OMAFAN_CTL` contains a space; `status`
  reports `stale-path` after the ctl path changes; the existing byte-identical
  install/remove assertions still pass.
- **Done:** `bash -n` clean; `bash tests/keybindings.test.sh` prints
  `PASS n / FAIL 0` with n ≥ 58; paste the emitted block and the `status` output
  from the tempdir run in your report.
