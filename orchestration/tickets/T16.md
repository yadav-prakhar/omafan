### T16 — adversarial review: safety, privilege, collisions, failure modes
- **Goal:** attack the plugin's blast radius. A previous fan plugin made the user
  install `/etc/udev/rules.d` and `/etc/polkit-1/rules.d` entries; omafan claims
  it needs none and never writes `/sys`. Verify that claim by looking for the
  opposite, and look for every way this plugin could leave the machine in a state
  the operator did not ask for.
- **Files (own):** `orchestration/REVIEW-R2.md` only. **Read-only everywhere
  else.** No git, no `OMAFAN_LIVE`/`OMAFAN_HW`, no writes to `/sys`, `/etc`,
  `/usr`, `/run/afanctl`, `~/.config/omarchy` or `~/.config/hypr`; run
  `omafan-ctl` only against `tests/fixtures/fake-afanctl` with `--pkexec none`
  and a tempdir runtime dir.
- **Method (do all of it, quote the commands):**
  1. **Write-path audit.** `grep` the whole tree (excluding `.git`, `orchestration/logs`,
     `docs/`) for every attempt to write anywhere: `>`, `>>`, `tee`, `mv`, `cp`,
     `rm`, `install`, `sed -i`, `mktemp` targets, QML `FileView`/`writeAdapter`.
     Classify each by destination and say whether it can leave the plugin's own
     directory, its backup dir, the runtime cache, `shell.json` (via `omarchy
     plugin enable`), or the managed `bindings.lua` block. Anything else is a
     blocker.
  2. **Privilege audit.** Show every `pkexec` invocation with its exact argv, and
     prove that no user-controlled string can add an argument, change the binary,
     or reach a shell. Check `--pkexec none`, `--afanctl`, `--runtime-dir` and the
     rpm/preset inputs for injection; confirm `set -euo pipefail`, quoting, and no
     `eval`. Confirm nothing in the plugin is ever run as root except `afanctl`
     itself, and that the polkit rule (`/usr/share/polkit-1/rules.d/49-afanctl.rules`)
     still pins `/usr/bin/afanctl` and the four allowed verbs.
  3. **Undercooling / fan-left-held audit.** Enumerate every path that can end
     with the fan in a hold: which of them can happen without a user action, what
     happens if the shell dies immediately after a write, what a `release` failure
     leaves behind, and whether the `release_after_minutes` safety net can be
     defeated (panel closed, shell restarted, setting changed mid-hold). Say
     plainly which cases are covered by afanctl's own model
     (see `/home/prakhar/Work/tries/2026-09-14-a1708-fanctl/README.md`) and which
     are omafan's responsibility.
  4. **Collision audit.** Verify by command, not by reading: the plugin id and IPC
     target are unique across `omarchy plugin list --json` and
     `omarchy-shell shell listPlugins`; the eight chords are free on the live
     `hyprctl binds -j` set *and* against the Lua sources including `code:`
     chords; no filename in the plugin directory shadows a path another plugin
     uses; the settings keys cannot collide with another plugin's `shell.json`
     entry; and the plugin defines no service, unit, port or environment variable
     that could clash. Report each with the command you used.
  5. **Failure-mode walk.** For each of: afanctl missing; daemon stopped;
     `state.json` stale; `monitor_only`; `auto_restore_pending`; runtime dir
     read-only; `pkexec` prompting for a password instead of the rule matching;
     `notify-send` absent; `jq` absent; shell restart mid-hold — say what the user
     sees, what the plugin does, and whether the state can be recovered without
     root. Reproduce the ones you can with the fixture (e.g. `FAKE_AFANCTL_MODE`,
     a read-only tempdir, a `jq`-less `PATH`) and quote the output.
  6. **Uninstall audit.** Trace `omarchy plugin remove io.github.yadav-prakhar.omafan`
     plus `bin/omafan-keybindings remove` and list everything that survives
     (files, backups, `shell.json` entries, the runtime cache, state files). Any
     leftover that changes behaviour is a finding.
- **Report format in `orchestration/REVIEW-R2.md`:** verdict up top, then findings
  numbered `R2-<n>` with severity (`blocker` / `should-fix` / `nit`), the
  reproducible command and observed output, the risk in plain language, and the
  smallest fix. Then the five audit tables (write paths, pkexec argv, hold paths,
  collisions, failure modes), and a final "what a stranger cannot break" list. No
  praise, no restating the ticket.
- **Done:** the report exists, every claim is backed by a command you ran, and
  nothing outside `orchestration/REVIEW-R2.md` changed.
