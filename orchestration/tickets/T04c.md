### T04c — `bin/omafan-ctl` fix round: the fast-path status document
- **Goal:** two defects found by the orchestrator against the **live** machine
  (`./bin/omafan-ctl status --json` with no flags, i.e. the fast path the panel
  polls every 2 s). Everything else you shipped is accepted — do not regress it.
- **Files (own):** `bin/omafan-ctl`.
- **D1 (defect, must fix):** the fast path hardcodes
  `thermal = {"t_eff_c": null, "sensors": []}` even though `/run/afanctl/state.json`
  carries `t_eff_c` (verified live: state.json had `"t_eff_c":54.0` while your
  document reported `"t_eff_c":null`). The bar widget falls back to its glyph and
  the panel header loses its headline temperature, so this is user-visible on
  every poll. Read `t_eff_c` from the state document; keep `null` only when it is
  genuinely absent. `sensors: []` is correct and expected on the fast path (the
  state file has no per-sensor detail) — add a code comment saying so, because the
  panel deliberately asks for `--full` when it needs the sensor list.
- **D2 (defect, must fix):** `daemon.uptime_s` is `null` on the fast path even
  though `polls` is present; `--full` reports it correctly. DESIGN §4.1 defines
  `uptime_s = polls × poll.interval_s`, and the interval is available from
  `afanctl status --json`'s `config.interval_s`. Persist `interval_s` in the
  hardware-limit cache (`$XDG_RUNTIME_DIR/omafan/hw.json`) whenever that cache is
  (re)written, and compute `uptime_s` from `polls × interval_s` on the fast path
  when the cached interval is known. When it is genuinely unknown, `uptime_s`
  stays `null` and a `warnings[]` entry says
  `"poll interval unknown; run omafan-ctl status --full once to cache it"`.
- **Gates (paste all of them):**
  1. `bash -n bin/omafan-ctl`.
  2. On this machine, with a cache dir that has been primed by one
     `--full` run: `./bin/omafan-ctl status --json` shows a numeric
     `thermal.t_eff_c` (equal to `/run/afanctl/state.json`'s `t_eff_c`) and a
     numeric `daemon.uptime_s`, and `polls × interval_s` equals it.
  3. With a cold cache dir (`--full` never run) the same command still shows a
     numeric `t_eff_c`, `uptime_s: null`, and the warning above.
  4. Against `tests/fixtures/fake-afanctl` with a seeded state, the §4.1 document
     still validates field-by-field the way your T04 transcript showed, and exit
     code 5 (daemon down) is unchanged.
  5. `./bin/omafan-ctl status --json --full` still returns the sensor list.
