# Ticket T04d (from PLAN.md — authoritative)

### T04d — `bin/omafan-ctl` BLOCKER fix: the privileged write path never runs
- **Goal:** fix a defect the orchestrator reproduced on the real machine. Your
  write path is *non-functional* whenever polkit is involved; only `--pkexec none`
  ever worked, which is why the fixture tests were green.
- **Files (own):** `bin/omafan-ctl`.
- **Evidence (orchestrator, on this machine):**
  - `pkexec /usr/bin/afanctl status --json` → returns in **0.026 s**, exit 0.
  - `pkexec env AFANCTL_RUNTIME_DIR=/run/afanctl /usr/bin/afanctl status --json`
    → **hangs** until killed (`timeout 6` → exit 124).
  - Your dry-run argv is
    `["/usr/bin/pkexec","env","AFANCTL_RUNTIME_DIR=/run/afanctl","/usr/bin/afanctl","hold","7200"]`.
  - Cause: afanctl's polkit rule (`/usr/share/polkit-1/rules.d/49-afanctl.rules`)
    re-checks `action.lookup("program") !== "/usr/bin/afanctl"` and then matches
    the argv exactly (`argv[0] == "/usr/bin/afanctl"`, `argv[1]` the verb). With
    `env` inserted, pkexec's `program` is `env`, the rule returns
    `NOT_HANDLED`, and pkexec falls back to asking a human for the root password —
    a graphical prompt that never gets answered from a script or the panel.
- **D1 (blocker, must fix):** the privileged argv must be exactly
  `[<runner>, <afanctl>, "hold", "<rpm>"]` / `[<runner>, <afanctl>, "observe"]`.
  No `env` wrapper, no extra arguments, nothing between the runner and the binary.
- **D2:** a custom runtime directory cannot ride along (the rule pins the argv, and
  pkexec sanitises the environment anyway — your own comment says so). So when the
  runner is **not** `none` and the resolved runtime dir is not afanctl's default
  (`/run/afanctl`, keep it in a named constant), **refuse the write** with exit 2
  and a message that names the cause and both fixes: "pkexec cannot carry a custom
  runtime dir (afanctl's polkit rule pins the argv, and pkexec sanitises the
  environment); writes target afanctl's default /run/afanctl — unset
  --runtime-dir/OMAFAN_RUNTIME_DIR, or use --pkexec none for tests". Reads still
  read the directory the user asked for (say so in the message).
- **D3 (robustness):** no invocation of the runner may hang the caller. Wrap every
  runner call in a bounded wait (`timeout 20`, or a poll-with-deadline) and turn a
  timeout into exit **3** with "authorisation timed out or was cancelled — is the
  polkit agent running? (pkexec falls back to a password prompt when
  /usr/share/polkit-1/rules.d/49-afanctl.rules does not match)". Same guard for
  `notify-send` (it returns in 10 ms here, but it must never be able to hang the
  write). A killed runner must not be reported as success.
- **D4:** `doctor` gains the check id `pkexec_write_path` (DESIGN §4.4's fixed id
  list is extended by this ticket, add it in the same place the others live):
  when `--pkexec` is `none` → `WARN` ("privileged writes disabled with --pkexec
  none"); otherwise run `[<runner>, <afanctl>, "status", "--json"]` with a 3 s
  deadline and report `PASS` ("polkit authorises /usr/bin/afanctl status --json in
  <ms> ms") / `FAIL` ("pkexec did not answer within 3 s — it is prompting for a
  password, so writes will hang; check the polkit rule and that the session is
  local and active") naming the fix. This makes the failure visible from
  `omafan-ctl doctor` instead of only at the moment a user presses a key.
- **Gates (paste all of them):**
  1. `bash -n bin/omafan-ctl`.
  2. On this machine: `./bin/omafan-ctl preset full --dry-run --json` shows
     `["/usr/bin/pkexec","/usr/bin/afanctl","hold","7200"]` — no `env`, no extra
     elements.
  3. On this machine, a real write through the runner completes in well under a
     second and the daemon reports the hold: run
     `./bin/omafan-ctl preset high` (or another preset at or above the current
     rpm — the machine is hot, so do **not** command a speed below the live rpm),
     then `./bin/omafan-ctl status --json | jq -c '.daemon.mode, .fan.target_rpm'`,
     then **`./bin/omafan-ctl release`** and confirm `mode=observe`,
     `manual=false`. Finish with `systemctl is-active afanctl` and the contents of
     `/run/afanctl/state.json` so the orchestrator can confirm you left the fan
     owned by the firmware.
  4. `./bin/omafan-ctl preset med --runtime-dir /tmp/other` exits 2 with the D2
     message and writes nothing.
  5. `./bin/omafan-ctl doctor --json | jq -r '.checks[] | select(.id=="pkexec_write_path")'`
     shows `PASS` with a millisecond figure.
  6. `bash tests/ctl.test.sh` still passes (it must not depend on the old argv).
