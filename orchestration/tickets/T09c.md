# Ticket T09c (from PLAN.md — authoritative)

### T09c — `Panel.qml` robustness fix: a command that never answers must not freeze the panel
- **Goal:** fix the panel behaviour exposed by a real defect: `omafan-ctl`'s write
  path could block for minutes (its `pkexec` fell back to a password prompt that
  nobody answers). The panel kept `busy = true` for the whole time, so every
  control in the UI stayed disabled with no explanation — indistinguishable from
  a crash. Ticket T04d fixes the underlying argv; this ticket makes the panel
  survive *any* runner that never answers.
- **Files (own):** `Panel.qml`.
- **D1:** every `Process` the panel owns gets a deadline (20 s is fine): if it is
  still running when the deadline fires, kill it, clear `busy`/`pendingRpm`, and
  set `lastError` to a message that names the symptom and the fix, e.g.
  "omafan-ctl did not answer within 20 s — a polkit password prompt may be waiting
  (run `omafan-ctl doctor`); the fan's last verified state is shown below". The
  banner must render that message (the panel already has a banner row).
- **D2:** a killed/never-answering command must never be rendered as if it had
  succeeded: no optimistic "Holding …" text; the mode/target must come from the
  next successful `status` poll only.
- **D3:** the panel must survive a `status` poll that fails or times out: keep the
  previous document but mark it (`state_stale`-style), and keep the poll timer
  running so the panel recovers by itself when `omafan-ctl` answers again. Add a
  visible "status stale" indicator rather than silently showing old numbers.
- **D4:** while `busy`, keyboard input must not queue up an unbounded number of
  commands (the debounce already coalesces slider writes — make sure preset
  presses while busy are ignored, not stacked).
- **Gates:** `bash tests/qml-lint.sh` passes; and a short written trace of the
  state machine for the three paths (normal write; write that times out; status
  poll that fails) showing `busy`, `lastError` and what the UI renders in each.
  If you can, exercise the timeout path with the factory fixture by pointing
  `OMAFAN_AFANCTL` at a stub that sleeps forever (a temp script outside the repo),
  and say what the panel did.
- **Done:** the trace; no changes outside `Panel.qml`.
