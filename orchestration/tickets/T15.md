# Ticket T15 (from PLAN.md — authoritative)

### T15 — adversarial review: code against the frozen contracts
- **Goal:** find where the shipped code does **not** match `DESIGN.md`, where a
  claim in `PRD.md` §4 is unsupported, and where behaviour exists that nobody
  specified. You are the adversary: assume the authors (other models) were
  over-confident, including in their own test suites.
- **Files (own):** `orchestration/REVIEW-R1.md` only. **Read-only everywhere
  else.** Do not edit source, do not run git, do not run tests that write
  (`OMAFAN_LIVE`, `OMAFAN_HW` are forbidden), do not touch `/run/afanctl`,
  `/sys`, `/etc` or `~/.config/omarchy`, and never invoke `omafan-ctl` without
  `--afanctl tests/fixtures/fake-afanctl --pkexec none --runtime-dir <tmpdir>`.
- **Scope of the review:** `manifest.json`, `Model.js`, `BarWidget.qml`,
  `Panel.qml`, `KeyboardHelp.qml`, `bin/omafan-ctl`, `bin/omafan-keybindings`,
  and the test files that gate them.
- **Method (do all of it, and report the commands you ran):**
  1. Enumerate every normative item in `DESIGN.md` §1-§7 and §10 (identity,
     preset model, CLI verbs/globals/exit codes, the four JSON schemas, the 19
     `Model.js` functions + §5.1, the QML contracts, the key maps, the test
     contract). For each: find the implementing code *and* the test that proves
     it. Produce a table with three verdicts only — `proved`, `implemented but
     untested`, `missing/divergent` — with `file:line` for both sides.
  2. Try to falsify the tests themselves: run them, then break one behaviour at a
     time in a **copy** under `/tmp` (never in this repo) and check the suite
     fails. A suite that stays green on a mutation is a finding.
  3. Look for unspecified behaviour that could surprise an operator: default
     values, error paths, what happens on the second identical command, what
     happens when `jq`/`notify-send` are absent, locale/LANG effects on number
     formatting, behaviour when the runtime dir is read-only, races between the
     poll timer and a write.
  4. Check the CLI's argument parsing for order-insensitivity, missing values
     (`--rpm` with no argument), repeated flags, `--` handling, and any place a
     user-supplied string reaches a command line unquoted.
  5. Verify the QML's claims against the installed shell sources (for example that
     `KeyboardPanel`/`PanelKeyCatcher` really are used the way the panel assumes,
     that `IpcHandler` method signatures match how `omarchy-shell` calls them, and
     that no `Panel.qml` when-clause can never fire).
  6. Re-read `PRD.md` §4 G1-G12 and mark each as verifiable-in-principle,
     verifiable-now, or unsupported by any artefact.
- **Report format in `orchestration/REVIEW-R1.md`:** a short verdict up top, then
  findings numbered `R1-<n>` with severity (`blocker` / `should-fix` / `nit`),
  the exact evidence (command + observed output), the contract clause it
  violates, and the smallest fix. Then the contract-coverage table from step 1,
  the mutation results from step 2, the "could not verify" list, and the PRD §4
  table from step 6. No praise, no summary of what the code does well, no
  restating the ticket.
- **Done:** the report exists, every finding is reproducible from the commands
  quoted in it, and you have changed nothing else in the tree.
